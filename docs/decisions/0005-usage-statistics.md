# ADR 0005: локальная статистика использования записей (frecency)

## Статус

Принято владельцем 2026-09-29.

## Контекст

Панель и launcher `/wp` должны показывать выше часто и недавно используемые
записи. Прежний список недавних жил в `noctalia.state`, который хранится только
в памяти процесса Noctalia и теряется при перезапуске. Долговременные данные
плагина по API Noctalia хранятся в `noctalia.pluginDataDir()`.

Entry ID — обратимое кодирование пути записи (`docs/SECURITY.md`), поэтому файл
с ID фактически раскрывает, какими записями и как часто пользуются. Имена
записей и так видны в именах файлов gopass-хранилища; новым раскрытием являются
только частота и время использования.

## Решение

- Плагин (Luau, не helper) хранит `pluginDataDir()/usage.json` вида
  `{"version":1,"entries":{"<entry-id>":{"score":<number>,"last_used":<unix ms>}}}`.
- Файл содержит только opaque entry ID и числа: без label, значений полей,
  текстов запросов и результатов copy. Не больше 200 записей; ID, отсутствующие
  в полном свежем `list`, удаляются при загрузке; битый файл читается как пустая
  статистика.
- Вес: `score·2^(−Δt/H)`, H — настройка `usage_half_life_days` (7/14/30,
  по умолчанию 14). Использование: `score = score·2^(−Δt/H) + w`,
  `last_used = now`; w = 1.0 для copy password/TOTP, 0.5 для другого поля,
  0.1 для открытия карточки. Отрицательный Δt считается нулём.
- Использование фиксируется при dispatch copy: результат copy плагину неизвестен.
- Настройка `smart_sort = false` отключает чтение и запись статистики; кнопка
  панели «Сбросить статистику» удаляет файл.
- Helper по-прежнему не пишет файлы (`TestProductionPersistenceAndExecTripwire`).

## Последствия

- Любой процесс с правами пользователя может прочитать частоту и время
  использования записей. Это принятое владельцем раскрытие.
- Panel и launcher — разные VM одного процесса, поэтому каждая запись делает
  read-modify-write файла; одновременная запись из двух entry может потерять
  одно обновление, что допустимо для ранжирования.
