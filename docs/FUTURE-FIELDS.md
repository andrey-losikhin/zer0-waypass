# Будущая карточка записи и произвольные поля

## Статус

Waypass Field Contract v1 принят и runtime-карточка использует отдельный
protocol v2. Protocol v1 остаётся совместимым.

## Требуемый UX Noctalia

Пользователь должен иметь возможность открыть карточку выбранной записи и
выбрать поле клавишами `1`–`9` (с отдельной навигацией для большего количества
полей). Активация поля копирует его значение в sensitive clipboard с тем же
ограниченным временем владения, что и текущие username/password actions.

Карточка показывает значения полей с contract visibility=`public`, включая
notes/host/port/database. Visibility=`secret` показывает только имя и Copy.
Никакие значения не сохраняются в Noctalia settings/cache или логах.

## Требуемая архитектура

- Go-helper получает opaque entry ID и отдельный идентификатор поля.
- Перед расшифровкой helper заново подтверждает entry membership.
- Имя поля валидируется как данные: ограниченная длина, UTF-8, без управляющих
  символов, option injection и shell; shell не используется.
- Значение выбранного поля передаётся напрямую `gopass -> wl-copy` по pipe и не
  читается Go-кодом или Noctalia.
- Для построения карточки нужен отдельный metadata-контракт имён полей. Нельзя
  расшифровывать запись и возвращать её содержимое в UI только ради списка.
- `gopass 1.16.1` не позволяет получить только live-имена полей: для этого
  пришлось бы расшифровать и разобрать всю запись. Такой обход запрещён.
- Разблокировка требует отдельной encrypted schema, атомарно связанной с entry;
  plaintext metadata index и недоказанное использование templates запрещены.
- Field ID должен быть связан с конкретной revision/content digest schema; copy
  повторно читает schema и fail-closed отклоняет stale/reordered mapping.
- Повторяющиеся поля и multiline/body не имеют однозначного field selector в
  подтверждённом CLI-контракте и должны fail-closed до отдельного extractor ADR.
- `password`, tokens, private keys и recovery codes скрыты. `notes` по принятому
  контракту public и показываются целиком; custom visibility задаёт TUI.

## Связь с TUI

Создание, изменение и удаление записей остаётся задачей отдельного
`zer0-gopass-tui`. Noctalia предназначена для быстрого поиска и копирования, а
не для ввода расшифрованных значений.

Будущий TUI может сопровождать encrypted schema, но этот репозиторий и текущий
milestone не меняют TUI и не создают schema автоматически.
